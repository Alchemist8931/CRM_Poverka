# Яндекс Карты: геокодирование, карта в конструкторе, Навигатор

Пункт плана **int-maps**. Что здесь описано: зачем системе карта, какие два
ключа ей нужны, во что это обходится при нашем объёме и какие условия Яндекса
приходится исполнять кодом, а не обещанием.

## Что делает карта в системе

**Сервер геокодирует адрес при сохранении заявки.** Приём и правка заканчиваются
обращением к HTTP Геокодеру, и в заявку ложатся широта, долгота, точность ответа
и адрес в том виде, как его понял Яндекс (`server/src/maps/place.ts`, столбцы
`requests.lat`, `lon`, `geo_precision`, `geo_address`, `geocoded_at`).
Геокодирование идёт после записи и не в транзакции: молчащий Геокодер не имеет
права отменить приём заявки.

**Конструктор маршрутов показывает точки дня на настоящей карте.** Порядок
объезда задаётся кликами, как и раньше; между выбранными точками ложится линия,
в шапке показывается оценка длины объезда. Кнопка «Упорядочить» раскладывает
выбранные точки по окнам приезда, а внутри окна — ближайшим соседом
(`web/src/geo.js`).

**У поверителя на каждой точке — кнопка «Навигатор».** Она открывает
`yandexnavi://build_route_on_map?lat_to=…&lon_to=…`; если приложения нет,
через секунду открываются Яндекс Карты в браузере. Кнопки нет у адресов без
координат: неработающая кнопка в телефоне на лестничной клетке хуже её
отсутствия.

**Без ключа всё работает.** Конструктор рисует прежнюю схематичную карту области
(города на условных местах, адреса подсолнухом), заявка сохраняется без
координат. Это и есть демо-режим на GitHub Pages, и это же — состояние контура,
где ключ ещё не завели.

## Точность важнее координаты

Геокодер отвечает всегда и почти никогда не говорит «не знаю»: не нашёл дом —
отдаст середину улицы, не нашёл улицу — центр города. Поэтому вместе с точкой
хранится точность ответа (`GeocoderMetaData.precision`):

| Значение | Что это | Можно ли вести по ней |
|---|---|---|
| `exact` | до дома | да |
| `number`, `near`, `range` | рядом с домом, дом в диапазоне номеров | да, с оговоркой в подсказке |
| `street` | только улица | нет: это середина улицы |
| `other` | город и грубее | нет |

Точка не «до дома» показывается на карте так же, но в подсказке к кнопке
Навигатора стоит оговорка «точка на улице, не на доме».

## Два ключа

Ключей из кабинета разработчика (`developer.tech.yandex.ru`) нужно два, и путать
их нельзя.

| Ключ | Где живёт | Чем защищён | Переменная |
|---|---|---|---|
| HTTP Геокодер | только на сервере | тем, что никуда не отдаётся | `YANDEX_GEOCODER_KEY` |
| JavaScript API | уходит в браузер | **ограничением по домену** в кабинете | `YANDEX_JSAPI_KEY` |

Ключ JS API спрятать невозможно в принципе: он стоит в адресе загрузки
библиотеки и виден в любой вкладке. Защищает его не секретность, а список
разрешённых доменов в кабинете разработчика — с чужого сайта запрос с этим
ключом отвергается. Поэтому фронт получает ключ от сервера
(`GET /api/maps/config`), а не из сборки: в сборке он оказался бы в репозитории,
откуда его уже не вычистить.

В облаке оба ключа приезжают из Lockbox по сервисному аккаунту ВМ: секрет
`<префикс>-maps`, записи `geocoder_key` и `jsapi_key`
(`server/src/secrets.ts`, `infra/variables.tf`). Секрет заводится пустым, значения
вносит человек в консоли. Ни ключа, ни его следа нет ни в репозитории, ни в
состоянии Terraform, ни в образе.

Домены, которые нужно разрешить ключу JS API: временный домен контура
(пункт cloud-infra) и боевой домен после переезда (cloud-domain). Больше нигде
система карту не показывает.

## Сколько это стоит при нашем объёме

Сведения сверены по сайту Яндекса **17.09.2026**. Перед оплатой их стоит
подтвердить в кабинете: тарифные страницы Яндекс правит без предупреждения, и
цифры на разных его страницах не всегда совпадают.

### Бесплатная лицензия

«Условия использования сервисов Яндекс Карт» (редакция от **01.09.2026**,
<https://yandex.ru/legal/maps_api/ru/>) дают бесплатно:

* **Геокодер — не более 1000 запросов в сутки** суммарно;
* **JavaScript API** — без суточного лимита на показ карты (отдельные лимиты
  стоят на Показ Панорам — 100 запросов в сутки — и на Static API — 100);
* хранение ответа — **не дольше 30 суток** («временное хранение (кэширование)
  результатов … на срок не более 30 дней»).

Плюс условия, которые надо исполнять, а не просто прочитать
(<https://yandex.ru/dev/commercial/doc/ru/>): сервис должен быть публично
доступен, копирайт и логотип Яндекса убирать нельзя, данные Яндекса можно
показывать только на его же картах, следить за людьми и машинами в реальном
времени бесплатной лицензией нельзя.

### Наш объём

Заказчик обслуживает порядка **110 адресов в день**. Обращений к Геокодеру
меньше, чем адресов:

* повторный адрес берётся из своей же базы (`requests` по городу, улице и дому) —
  а повторов у поверки счётчиков много: тот же дом, та же улица, соседняя
  квартира;
* правка заявки, не трогающая адрес, Геокодер не беспокоит;
* ежесуточная чистка (`npm run maps:prune`) заново геокодирует только адреса
  **предстоящих** выездов — это десятки строк, не сотни.

Даже если считать, что каждый адрес новый и каждый день заново, получается
**110–150 запросов в сутки при лимите 1000** — запас примерно семикратный.
Бесплатной лицензии по объёму хватает.

### Где бесплатная лицензия кончается

Не в объёме, а в праве **хранить координаты дольше 30 суток**. Система хранит их
в заявке, и это ровно то, что бесплатные условия разрешают только как временное
кеширование. Поэтому в коде стоит настройка `GEO_CACHE_DAYS`, по умолчанию 30:

* ответ старше срока не переиспользуется — адрес геокодируется заново;
* ежесуточное обращение `npm run maps:prune` снимает просроченные координаты, а
  адресам предстоящих выездов находит их заново (`pruneStale`).

Это честное исполнение условия, а не его обход. Если заказчик захочет хранить
координаты бессрочно (например, чтобы строить отчёты по географии за год), нужна
коммерческая лицензия, и тогда ставится `GEO_CACHE_DAYS=0` — обращение
выключается само.

### Цены, если лицензия понадобится

Годовая лицензия на **Геокодер** (<https://yandex.ru/maps-api/products/geocoder-api>):

| Лимит в сутки | Стандартная лицензия | Расширенная лицензия |
|---|---|---|
| до 1 000 | 195 000 ₽/год | 226 200 ₽/год |
| до 10 000 | 585 000 ₽/год | 678 600 ₽/год |
| до 25 000 | 1 105 000 ₽/год | 1 281 800 ₽/год |

Превышение — 390 ₽ за каждую тысячу запросов сверх суточного лимита.

**JavaScript API** (<https://yandex.ru/dev/tariffs/doc/ru/jsapi/prices>):
195 000 ₽/год или 41 600 ₽/мес за 500 запросов в сутки, безлимитная лицензия —
234 000 ₽/год; пробный период — 100 запросов в сутки на 7 дней; отключение
рекламы на карте — 2 000 ₽/мес или 20 000 ₽/год за домен.

Ориентир для разговора с заказчиком: **пока хватает бесплатной лицензии, карта
не стоит ничего**; первая причина платить — не рост числа заявок (до лимита
далеко), а желание хранить координаты дольше месяца. Это порядка 200 тысяч
рублей в год, и решение это не техническое, а хозяйское.

## Что где лежит

| Файл | Что делает |
|---|---|
| `server/src/maps/config.ts` | ключи, адрес Геокодера, срок хранения |
| `server/src/maps/geocoder.ts` | клиент HTTP Геокодера и разбор ответа |
| `server/src/maps/place.ts` | кеш по своей базе, запись в заявку, чистка по сроку |
| `server/src/api/routes/refs.ts` | `GET /maps/config` — ключ JS API фронту |
| `server/scripts/maps-prune.mts` | ежесуточная чистка просроченных координат |
| `server/migrations/1757981000000_maps.sql` | координаты и точность в `requests` |
| `web/src/ui/ymaps.js` | загрузка JS API 3.0 и живая карта под перерисовку |
| `web/src/geo.js` | расстояния, порядок объезда, ссылки в Навигатор |
| `web/src/screens/route-builder.js` | конструктор: настоящая карта и схема области |

Версия библиотеки — **JavaScript API 3.0** (`https://api-maps.yandex.ru/v3/`),
текущая у Яндекса. Длина маршрута считается по прямой с поправкой на
извилистость улиц (коэффициент 1.3), а не по дорогам: маршрутизация по дорогам —
это отдельный платный продукт и обращение на каждую пару точек, а руководителю
нужен порядок объезда и понимание «это полдня или весь день», а не расписание до
минуты. Поэтому длина везде подписана «≈».

## Проверки

```
cd server && npx tsx scripts/check-maps.mts      # геокодирование, кеш, срок хранения
cd web && npm run build && node scripts/check-maps-ui.mjs   # карта в конструкторе, Навигатор, демо
```

Обе проверки к настоящему Яндексу не ходят: у них нет ключа, и зависеть от чужой
службы и её суточного лимита они не имеют права. Геокодеру подставлен свой
приёмник, отвечающий тем же JSON; библиотека карты заменена заглушкой с тем же
набором классов, что у JS API 3.0. Наш код при этом работает настоящий — и
клиент Геокодера, и загрузчик, и конструктор.

Чего этими проверками не проверить и что нужно сделать, когда ключ появится:

1. `YANDEX_GEOCODER_KEY=… npx tsx scripts/check-maps.mts --live` — настоящий
   Геокодер на тестовых адресах в Асбесте и Екатеринбурге должен отвечать
   точностью `exact`.
2. Открыть конструктор на контуре с ключом и посмотреть, как выглядит и ведёт
   себя настоящая карта: заглушка проверяет наши вызовы, а не поведение Яндекса.
3. Проверить ограничение ключа по домену: с чужого адреса карта грузиться не
   должна.
