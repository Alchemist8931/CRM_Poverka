# Инструкции по ролям, видео и обучение

Пункт плана **docs-train**. Здесь собираются четыре инструкции (.docx), план
обучения с чек-листом и четыре коротких видео. Готовые файлы лежат в файлах
чата заказчика, в репозитории — только то, из чего они собираются.

| Что | Где |
|---|---|
| Текст инструкций | `content/operator.mjs`, `supervisor.mjs`, `verifier.mjs`, `admin.mjs`; план обучения — `training.mjs` |
| Адрес системы, поддержка, версия | `content/common.mjs` — единственное место; после переезда на постоянный домен меняется одна константа и документы пересобираются |
| Скриншоты | `shots/*.png`, снимает `shots.mjs` с локального стенда (тот же `web/dist`, что выложен на dev) |
| Видео | `video.mjs` → `video/*.webm` + `.srt`; субтитры рисуются в кадре, mp4 — через ffmpeg |
| Сверки | `check-names.mjs` — названия экранов и кнопок из инструкций есть в `web/src`, скриншоты на месте; `check-caps.mjs` — встроенные подсказки экранов (`CAPS` в `web/src/refs.js`) раскрыты в инструкциях тех ролей, что их видят; `check-admin-flow.mjs` — сценарий заведения сотрудника по инструкции администратора нажатиями, без внутренних вызовов |

## Как пересобрать

```bash
cd web && npm run build && cd ../docs/train
node stand.mjs &                 # стенд: PGlite + web/dist, sv/o2/v2 с паролем 1234
node shots.mjs                   # скриншоты → shots/
node build-docs.mjs              # документы → out/
node video.mjs [роль]            # видео → video/
node check-names.mjs             # сверка названий (код 0)
node check-caps.mjs              # подсказки экранов раскрыты в инструкциях (код 0)
node to-mp4.mjs [путь-к-ffmpeg]   # video/mp4/*.mp4 + .srt; ролик длиннее 4 минут ускоряется до 10 %, .srt пересчитывается (код 0)
node with-stand.mjs check-admin-flow.mjs   # сценарий заведения сотрудника (код 0)
```

Ролики по заданию 2–4 минуты; запись идёт в реальном времени, и на медленном
стенде выходит на десяток секунд длиннее — `to-mp4.mjs` это выравнивает. Если
ролик длиннее 4:24, скрипт вернёт код 1: сценарий нужно сократить и перезаписать.

Из `.docx` после сборки убирается пустая часть комментариев, которую кладёт
docx-js: `python3 strip_comments_part.py <файл>` (скрипт в корне песочницы).
Внутри документов нет комментариев, выделений и пометок — все оговорки идут в
отчёт по задаче, не в файл.

## Что где в инструкциях

- **Оператор:** вход, приём заявки (подсказка дат, повторный клиент, дубль,
  приём закрыт), обзвон накануне, поддержка дня, лист ожидания, заработок.
- **Руководитель:** план дня и смены, сборка маршрута и заявка на закрытую
  дату, контроль, подотчёт и долги, прайс, «Аршин», журнал.
- **Поверитель (телефон):** маршрут, акт и закрытие позиции, непригодный прибор
  с бумажными бланками и заменой, «не обслужена», отдельный раздел про экран
  «Нет связи», подотчёт.
- **Администратор:** завести сотрудника и выдать временный пароль (главный
  сценарий), роль и компетенции, сброс пароля, блокировка при увольнении,
  прайс, что делать при оповещении о сбое, журнал.
- **План обучения:** две встречи по часу (операторы с руководителем; поверители),
  поминутно, с чек-листами усвоения по ролям и критерием готовности к пилоту.
