# Приёмочные испытания: контур, журнал замечаний, результаты

Пункт плана **test-uat**. Программа испытаний для заказчика — файл
«Учёткин — программа приёмочных испытаний.docx» (собирается из
`e2e/program/build.py`), автотесты на те же сценарии — `e2e/tests`, нагрузка —
`e2e/load/run.mjs`. Здесь — рабочая часть: что за контур, кто в нём есть,
что нашли и что с этим стало.

## Тестовый контур

| Что | Где |
|---|---|
| Адрес | `http://84.201.139.101` — dev в Яндекс Облаке по IP. Имя `84-201-139-101.sslip.io` заведено в конфигурации, TLS выключен (`infra/dev.tfvars`, `tls_enabled`; включение — пункт `live-tls`). **С 18.09.2026 этот контур — рабочий** (пункт `live-ip`, `docs/ops.md`, «Рабочий контур на временном адресе»): демо-данные из базы убраны, автотесты на него по расписанию не ходят |
| Машина | `crm-uchetkin-prod` (зона `ru-central1-b`), узел шлюза «CRM Учеткин»; приложение в `/opt/uchetkin`, исходники в `/opt/uchetkin/src` |
| Сборка | образы `uchetkin-api:manual` и `uchetkin-web:manual` собираются на самой машине из `main` — SSH с runner'ов GitHub закрыт, выкладка через Actions пропускается (`docs/release.md`, «Чего ещё нет») |
| База | PostgreSQL контейнером на ВМ (`managed_postgres = false`), хранилище снимков — бакет `uchetkin-dev-acts` |
| Данные | на время испытаний — `server/scripts/uat-stand.mts`: обезличенный демо-набор (вымышленные имена и телефоны), справочники через тот же импорт, что поедут данные заказчика (`be-import`, книга из `server/test/fixtures/refs-template.xlsx`), у сотрудников набора логины сняты. 18.09.2026 набор убран скриптом `server/scripts/purge-demo.sql` (остались только справочники), `uat-stand` и `npm run seed` на рабочем контуре больше не запускать |
| Учётные записи | две полного доступа — `owner` (владелец проекта) и `berdinskikh` (заказчица), временные пароли — в секрете Lockbox `uchetkin-handover` каталога `default` (владелец читает в консоли и удаляет после передачи), при первом входе меняются. Техническая `autotest` для CI и нагрузки на рабочем контуре удалена: перед ручным прогоном её заводит `uat-stand`, а он же стирает данные — на рабочем контуре это недопустимо, поэтому прогоны идут против локального стенда `e2e/stand.mjs` |

Как перезалить контур с машины (данные испытаний стираются):

```bash
cd /opt/uchetkin && sudo bash uat-stand.sh          # см. текст ниже
```

`uat-stand.sh` поднимает контейнер `node:22-alpine` с исходниками из
`/opt/uchetkin/src/server`, ставит зависимости и запускает
`npm run uat:stand -- --yes` со строкой подключения из `db.env`. Пароль
технической учётки — переменная `UAT_BOT_PASSWORD` (тот же, что в секрете
`UAT_PASSWORD` репозитория).

Автотесты против контура идут двумя путями, потому что из песочницы
разработчика порт 80 наружу закрыт:

- GitHub Actions — `.github/workflows/uat.yml`, адрес из переменной
  `UAT_BASE_URL`, учётка из секретов; с 18.09.2026 только по кнопке —
  расписание, запуск на push и после выкладки сняты, потому что контур
  рабочий;
- с самой машины — контейнер Playwright против `http://127.0.0.1`:

```bash
cd /opt/uchetkin/src && sudo docker run --rm --network host \
  -v "$PWD/e2e:/e2e" -w /e2e -e UAT_BASE_URL=http://127.0.0.1 \
  -e UAT_LOGIN=autotest -e UAT_PASSWORD=… -e UAT_STAFF_PASSWORD=… \
  mcr.microsoft.com/playwright:v1.56.1-noble sh -c 'npm ci && npx playwright test'
```
