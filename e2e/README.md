# Приёмочные сценарии и нагрузка

Пункт плана **test-uat**. Сквозные сценарии по ролям против живого контура,
локальный стенд для их разработки и нагрузочный прогон. Программа испытаний
для заказчика собирается из `program/build.py`; журнал замечаний и результаты —
в [`../docs/uat.md`](../docs/uat.md).

## Против облачного dev

```bash
cd e2e && npm ci && npx playwright install chromium
UAT_BASE_URL=https://uchetkin.ru UAT_LOGIN=autotest UAT_PASSWORD=… npx playwright test
```

Ничего не поднимается: браузер ходит на контур, техническая учётка входит,
`global-setup.mjs` заводит (или чинит) сотрудников испытаний `uat.op` и
`uat.ver` и ставит бригаду на две даты. Сценарии идут по порядку одним
воркером — каждый следующий опирается на данные предыдущего:

| Файл | Что проходит |
|---|---|
| `01-staff` | руководитель заводит сотрудника на экране, первый вход со сменой пароля, замок после пяти попыток, сброс, увольнение |
| `02-intake` | подсказка дат под услуги и город, приём заявки оператором, карточка известного клиента, дубль, замок даты |
| `03-plan` | планирование дня и смен, график, правило «не больше пяти городов», отсутствие с согласованием |
| `04-routes` | конструктор и замок даты, сборка, назначение поверителя, обзвон точек на экране поддержки |
| `05-verifier` | телефон поверителя: акт, фото в хранилище, пенсионер, «не годен» с номером бланка, наличные, перевод, «не обслужена» |
| `06-money` | подотчёт, сдельная, сдача руководителю |
| `07-waitlist` | лист ожидания: перенос адреса в маршрут |
| `08-arshin` | выгрузка во ФГИС «Аршин», файл, ответ реестра по строке |
| `09-offline` | потеря связи на телефоне: слой поднимается и снимается сам |

В CI это `.github/workflows/uat.yml`: после каждой удачной выкладки в dev,
каждую ночь, по кнопке и на правку самих сценариев. Учётные данные — секреты
репозитория `UAT_LOGIN`, `UAT_PASSWORD`, `UAT_STAFF_PASSWORD`, адрес —
переменная `UAT_BASE_URL`.

## Локально, без облака

```bash
cd web && npm run build
cd ../e2e && node stand.mjs            # доводы передаются playwright test
```

`stand.mjs` поднимает то же приложение на встроенном PostgreSQL
(`server/scripts/dev-pglite.mts`) и раздаёт собранный фронт с проксированием
`/api`. Хранилища снимков здесь нет — шаг с фото сценарий пропускает и
помечает это в отчёте.

## Тестовый контур

Данные контура готовит `server/scripts/uat-stand.mts` (`npm run uat:stand -- --yes`
в `server/`): обезличенный набор, справочники через импорт, ни одной учётки у
сотрудников, две учётки полного доступа и техническая `autotest`. Как это
запускается на машине dev — в `docs/uat.md`.

## Нагрузка

```bash
node load/run.mjs --minutes 60 --users 10 --requests 200 --photos 300
```

Десять сессий открывают основные экраны и по расписанию принимают заявки и
кладут снимки в акты тем же кругом, что телефон. Порог — p95 экрана не хуже
1000 мс. Итог — таблица в консоли и `load/out/<дата>.json`; код возврата 1,
если хоть один экран не уложился.
