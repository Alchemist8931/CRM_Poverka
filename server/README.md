# Серверная часть CRM «Учёткин»

REST API с доступом по ролям, схема базы, миграции, наполнение демо-данными
прототипа и импорт данных заказчика. Описание API — в [`../docs/api.md`](../docs/api.md),
таблиц и связей — в [`../docs/schema.md`](../docs/schema.md), импорта —
в [`../docs/import.md`](../docs/import.md).

Стек по архитектурному решению: Node.js 22, TypeScript, Fastify, PostgreSQL 16
(в облаке — Managed Service for PostgreSQL).

## Начать

```bash
docker compose up -d      # из корня репозитория: база, MinIO, API и фронт
curl -s localhost:3000/health
```

Руками, без Docker:

```bash
cp env.example .env
npm install
npm run migrate:up
npm run seed              # заодно заводит демо-учётки: логин = id сотрудника, пароль 1234
npm start                 # API на localhost:3000, описание по /docs
```

Без Docker и без PostgreSQL на машине — тот же API на встроенной базе
(PostgreSQL, собранный в WebAssembly); этим стендом проверяется фронт:

```bash
npx tsx scripts/dev-pglite.mts 3000   # миграции, демо-набор и API за полминуты
```

## Команды

| Команда | Что делает |
|---|---|
| `npm start` | поднять API (`PORT`, по умолчанию 3000) |
| `npm run dev` | то же с перезапуском по правкам |
| `npm test` | правила и весь API на PostgreSQL в WebAssembly, без Docker |
| `npm run migrate:up` | применить непринятые миграции |
| `npm run migrate:down` | откатить последнюю |
| `npm run migrate:redo` | откатить последнюю и применить заново |
| `npm run migrate:cloud` | то же, что `migrate:up`, но строка подключения берётся из Lockbox — шаг выкладки, см. `docs/release.md` |
| `npm run seed` | наполнить демо-данными прототипа (откажется, если база не пуста) |
| `npm run seed -- --reset` | очистить таблицы и наполнить заново |
| `npm run db:reset` | снести всё, применить миграции, наполнить |
| `npm run import -- refs <книга.xlsx>` | справочники заказчика: города, прайс, приборы (`--dry-run`, `--report`) |
| `npm run import -- clients <файл.xlsx>` | клиентская база: телефоны, адреса, прошлые поверки (`--map`, `--dry-run`) |
| `npm run typecheck` | проверка типов |
| `npm run check` | все проверки ниже подряд |
| `npm run check:photos` | круг снимка против живого хранилища: загрузить → миниатюра → открыть оригинал |

`npm run check` не требует ни Docker, ни базы на машине: он поднимает настоящий
PostgreSQL, собранный в WebAssembly, во временном каталоге. Подробности и
особенности стенда — в `docs/schema.md`, раздел «Проверка».

| Проверка | Что подтверждает |
|---|---|
| `check:model` | перенесённые куски прототипа лежат в `index.html` дословно, отпечаток набора совпадает |
| `check:docs` | `docs/schema.md` на месте и описывает каждую таблицу схемы |
| `check:tables` | заведены все таблицы и индексы из перечня пункта be-schema |
| `check:schema` | миграции вверх → откат последней → вверх → наполнение → объём набора |
| `check:seed-cli` | `npm run seed` наполняет пустую базу, отказывает по непустой, проходит с `--reset` |
| `check:import` | импорт через командную строку: пробный прогон не пишет, повтор не меняет, учётки не заводятся |
| `check:audit-prune` | `npm run audit:prune` убирает из журнала просроченное и не трогает записи моложе трёх лет |

### Импорт данных заказчика

`npm run import` грузит книгу справочников из пункта req-refs и клиентскую базу
из старого учёта. Пробный прогон (`--dry-run`) показывает, что будет создано и
что отвергнуто, `--report отчёт.xlsx` складывает отвергнутые строки с причинами
в файл для возврата заказчику, повторный запуск на том же файле ничего не меняет.
Учётные записи импорт не создаёт — ни одной. Подробности и карта столбцов —
в [`../docs/import.md`](../docs/import.md).

### Хранилище снимков

Фото акта лежат в Object Storage: на машине разработчика — MinIO из
`docker-compose.yml`, в облаке — Yandex Object Storage. Код один
(`src/storage.ts`), разница только в `S3_ENDPOINT` и ключе; ключ в облаке
приходит из Lockbox по сервисному аккаунту ВМ. Круг «загрузить → миниатюра →
открыть оригинал» проверяется против живого хранилища:

```bash
docker compose up -d minio minio-init
npm run check:photos          # против другого адреса — с S3_ENDPOINT и ключом в окружении
```

Проверки из `npm test` хранилища не требуют: там карта в памяти с тем же
интерфейсом, а без настроек хранилища загрузка отвечает 503 и рисуется заглушка.

## Правило про `prototype-model.mjs`

Файл собран из кусков `index.html` дословно, чтобы демо-набор в базе совпадал с
тем, что показывает прототип: генератор там с фиксированным зерном, и любая
перестановка строк меняет поток случайных чисел, а с ним и весь набор.

Поменялась модель в прототипе — блоки переносятся сюда заново целиком, руками в
этом файле ничего не правится. `npm run check:model` следит за этим и валится,
назвав разошедшийся блок и первую расходящуюся строку.
