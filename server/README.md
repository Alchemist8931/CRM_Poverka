# Серверная часть CRM «Учёткин»

Схема базы, миграции и наполнение демо-данными прототипа. Описание таблиц и связей —
в [`../docs/schema.md`](../docs/schema.md).

Стек по архитектурному решению: Node.js 22, TypeScript, PostgreSQL 16 (в облаке —
Managed Service for PostgreSQL). REST API на Fastify появится пунктом **be-api**.

## Начать

```bash
docker compose up -d      # PostgreSQL на localhost:5432
cp env.example .env
npm install
npm run migrate:up
npm run seed
```

## Команды

| Команда | Что делает |
|---|---|
| `npm run migrate:up` | применить непринятые миграции |
| `npm run migrate:down` | откатить последнюю |
| `npm run migrate:redo` | откатить последнюю и применить заново |
| `npm run seed` | наполнить демо-данными прототипа (откажется, если база не пуста) |
| `npm run seed -- --reset` | очистить таблицы и наполнить заново |
| `npm run db:reset` | снести всё, применить миграции, наполнить |
| `npm run typecheck` | проверка типов |
| `npm run check` | все проверки ниже подряд |

`npm run check` не требует ни Docker, ни базы на машине: он поднимает настоящий
PostgreSQL, собранный в WebAssembly, во временном каталоге. Подробности и
особенности стенда — в `docs/schema.md`, раздел «Проверка».

| Проверка | Что подтверждает |
|---|---|
| `check:model` | перенесённые куски прототипа лежат в `index.html` дословно, отпечаток набора совпадает |
| `check:docs` | `docs/schema.md` на месте и описывает каждую таблицу схемы |
| `check:tables` | заведены все таблицы и индексы из перечня пункта be-schema |
| `check:schema` | миграции вверх → откат последней → вверх → наполнение → объём набора |
| `check:seed-cli` | `npm run seed` наполняет пустую базу, отказывает по непустой, проходит с `--reset` |

## Что где лежит

```
migrations/                 SQL-миграции, node-pg-migrate
  …_reference.sql           города, услуги, типы приборов, сотрудники, компетенции
  …_operations.sql          дни, отсутствия, клиенты, заявки, маршруты, акты, деньги
  …_comms_and_audit.sql     звонки, переписка по маршруту, журнал действий
src/
  db.ts                     соединение, нормализация телефона, время в поясе заказчика
  seed/
    prototype-model.mjs     дословные куски index.html — НЕ ПРАВИТЬ РУКАМИ
    prototype-model.d.mts   типы того, чем пользуется загрузчик
    load.ts                 раскладка состояния прототипа по таблицам
    index.ts                запуск наполнения из командной строки
scripts/
  check-schema.ts           миграции вверх/вниз/вверх и наполнение на временной базе
  check-model-sync.mts      сверка перенесённой модели с index.html
  pglite-server.mts         временный PostgreSQL по сети, для ручных прогонов
```

## Правило про `prototype-model.mjs`

Файл собран из кусков `index.html` дословно, чтобы демо-набор в базе совпадал с
тем, что показывает прототип: генератор там с фиксированным зерном, и любая
перестановка строк меняет поток случайных чисел, а с ним и весь набор.

Поменялась модель в прототипе — блоки переносятся сюда заново целиком, руками в
этом файле ничего не правится. `npm run check:model` следит за этим и валится,
назвав разошедшийся блок и первую расходящуюся строку.
